# SPEC: 着地見込み方式のバックテストスクリプト

## 目的
着地見込みの計算方式を4種類、過去の実データで巻き戻し比較し、採用方式をデータで決める。
背景と全体方針は `deep-think_着地見込み鮮度差対応_2026-07-18.md` §結論-8 を参照。

## 変更対象
- 新規作成のみ：`scripts/forecast-backtest.ts`
- 既存ファイルの変更は一切禁止（src/ 配下、他の scripts/ にも触らない）

## 前提知識
- 日次売上は Supabase の `sales_unified_daily` VIEW（列: sale_date, platform('dlsite'|'fanza'|'youtube'), revenue ほか）から取得する。接続方法・環境変数の読み方は既存の `scripts/check-youtube-status.ts` 等のパターンを踏襲する
- プラットフォームごとにデータ確定ラグがある：`LAG = { dlsite: 1, fanza: 2, youtube: 3 }`（日）
- 「シミュレーション日 D に見えていたデータ」= プラットフォーム p の `sale_date <= D - LAG[p]` の行、と近似する（過去の暫定値→確定値の変動は再現不能。この近似前提をスクリプト冒頭コメントに明記すること）

## 要求仕様
1. 対象期間：2026-02〜2026-06 の5完了月。各月の各日 D（1日〜月末日）を「シミュレーション日」として、その時点の見込みを4方式で計算する。レート窓が前月にかかるため、データ取得は 2026-01-01〜2026-06-30 の日次×プラットフォーム別売上合計（1回のクエリでまとめて取得し、以後はメモリ内で計算）
2. 記号：`C_p = min(D - LAG[p], 対象月の月末日)`（p の確定日）。`C_min = min_p(C_p)`。「暦日ゼロ埋め」= 窓内にレコードのない日は売上0として平均に含める。残日数は実日付差で計算（月跨ぎで破綻しないこと）
3. 4方式（いずれも 見込み = 実績成分 + テール成分）：
   - **方式1（現行）**：全PF合算の日次系列で「データが存在する日」の直近3日平均 × (月末日 − 最終存在日)。実績成分 = D時点で見えている当月全行の合計。現行実装 `src/lib/queries/dashboard.ts:459-472` の忠実な再現とする（読むのは可、変更は不可）
   - **方式2（共通打ち切り・案A）**：実績 = 全PFの月初〜C_min 合計。テール = [C_min−2, C_min] の3暦日ゼロ埋め合算平均 × (月末 − C_min)
   - **方式3（PF別窓）**：PFごとに 実績_p = 月初〜C_p、テール_p = [C_p−2, C_p] の3暦日ゼロ埋め平均 × (月末 − C_p)。合算
   - **方式4（共通窓＋PF別実績）**：PFごとに 実績_p = 月初〜C_p、レート_p = [C_min−2, C_min] の3暦日ゼロ埋め平均、テール_p = レート_p × (月末 − C_p)。合算
4. 正解値：その月の最終確定売上合計（全データでの月合計）
5. 指標（方式ごとに算出）：
   - 符号付き平均誤差率：mean((見込み − 正解) / 正解)（過小バイアスが負に出る）
   - MAE率：mean(|見込み − 正解| / 正解)
   - 日次変動率：mean(|見込み(D) − 見込み(D−1)| / 正解)（D≥2）
   - 上記を (a)全期間 (b)月内フェーズ別（1〜5日／6〜15日／16日〜月末） (c)月別 で集計
6. 出力：コンソールに Markdown 形式の集計表（方式×指標、フェーズ別・月別も）。加えて生の日次見込み値を `scripts/output/forecast-backtest-raw.json` に保存（ディレクトリがなければ作成）
7. 計算ロジック（4方式の見込み計算・窓・日付演算）は DB 取得と分離した純粋関数として実装し、`--fixture` フラグ付き実行時は DB に接続せず、スクリプト内に埋め込んだ小さな合成データ（3PF×2ヶ月分程度、手計算で検算できる値）で全方式を実行して期待値と一致することを assert する（自己テスト）
